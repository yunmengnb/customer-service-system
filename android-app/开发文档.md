# 忆梦云客服 Android APP 开发文档

## 1. 项目目标

在 `android-app` 目录开发客服人员使用的 Android APP。APP 使用 Capacitor 承载现有用户后台，固定访问：

```text
https://user.ymfk.top
```

APP 前台沿用现有 Socket.IO 实时通信；退到后台或进程被系统清理后，通过个推在通知栏接收客户新消息。点击通知后打开对应会话。

> 生产环境禁止使用 `http://user.ymfk.top`。登录凭证和聊天内容必须通过 HTTPS 传输，Android 也默认限制明文 HTTP。

## 2. 技术方案

| 模块 | 技术 |
| --- | --- |
| Android 容器 | Capacitor + Android 原生工程 |
| 页面 | 远程 WebView，加载现有 Vue 用户后台 |
| 前台实时消息 | 现有 Socket.IO |
| 后台系统通知 | 个推 Android SDK |
| 原生桥接 | 自定义 Capacitor Plugin |
| 服务端推送 | Node.js 调用个推 REST API |
| 设备数据 | MongoDB `PushDevice` 集合 |
| 凭证 | 现有租户用户 JWT |

不采用“仅 WebView + Socket.IO”作为最终方案，因为应用退到后台或被杀死后，Android 不保证 WebView 和 Socket.IO 继续运行。

## 3. 工程边界

```text
android-app/
├─ package.json
├─ capacitor.config.ts
├─ src/
│  ├─ index.html
│  ├─ app.ts
│  └─ native-bridge.ts
├─ android/
│  └─ Android 原生工程
└─ 开发文档.md
```

APP 工程只负责：

- WebView 容器、启动页、图标和版本信息。
- 个推 SDK 初始化及 ClientId 获取。
- 通知权限申请、通知点击和前后台状态判断。
- Web 页面与原生层之间的消息桥接。
- 文件选择、相机、下载和 Android 返回键适配。

现有业务页面、登录和聊天功能继续由 `user-web` 提供。服务端设备绑定和推送逻辑在 `server` 与 Docker 版 `KF/server` 中同步实现。

## 4. 当前系统契约

### 4.1 登录状态

用户端当前使用以下键保存登录信息：

```text
tenant_token
tenant_user
tenant_info
```

请求通过：

```http
Authorization: Bearer <tenant_token>
```

APP 不读取或保存 JWT 到 Android 原生日志。远程页面登录成功后，由网页调用原生桥接触发设备绑定；后端仍使用当前 JWT 判断 `tenantId` 和 `userId`，不能信任网页提交的用户身份字段。

### 4.2 消息页面

手机消息列表：

```text
/m/messages
```

手机会话页面：

```text
/m/messages/:conversationId
```

通知点击后应导航到：

```text
https://user.ymfk.top/m/messages/{conversationId}
```

如果尚未登录，先打开登录页并保存待跳转会话；登录成功后再进入目标会话。

### 4.3 实时消息

Socket.IO 身份：

```js
{
  type: 'tenant_user',
  token: '<tenant_token>'
}
```

主要事件：

```text
message.new
conversation.created
conversation.updated
presence:changed
```

APP 页面前台时继续处理这些事件。后台推送只能作为提醒，打开页面后必须重新通过 HTTP 获取会话和消息，不能将推送载荷视为完整消息记录。

## 5. 个推接入设计

### 5.1 所需配置

个推控制台需要创建 Android 应用并提供：

```text
AppId
AppKey
AppSecret
MasterSecret
Android 包名
```

建议包名：

```text
com.yimeng.customer.service
```

配置安全边界：

- `AppId`、`AppKey` 按个推 Android SDK 要求配置到 Android 工程。
- `AppSecret` 和 `MasterSecret` 仅存放在服务端环境变量。
- 任何密钥都不得提交到 Git、写入网页源码或打印到日志。

建议服务端环境变量：

```env
GETUI_APP_ID=
GETUI_APP_KEY=
GETUI_MASTER_SECRET=
GETUI_BASE_URL=https://restapi.getui.com/v2
```

### 5.2 ClientId 生命周期

1. APP 启动并初始化个推 SDK。
2. SDK 返回 ClientId。
3. 网页登录成功后获取当前 JWT。
4. 网页通过原生桥接请求绑定设备。
5. 原生层或网页调用后端绑定接口。
6. ClientId 更新时重新绑定并停用旧记录。
7. 用户退出登录时解除当前账号绑定，但不注销个推 SDK。

一个客服账号允许绑定多台设备；一台设备重新登录其他账号时，服务端应覆盖该 ClientId 的旧归属。

## 6. 服务端数据模型

新增 `PushDevice`：

```js
{
  tenantId: ObjectId,
  userId: ObjectId,
  clientId: String,
  platform: 'android',
  appId: String,
  enabled: Boolean,
  lastSeenAt: Date,
  createdAt: Date,
  updatedAt: Date
}
```

索引要求：

```text
clientId 唯一索引
{ tenantId: 1, userId: 1, enabled: 1 }
```

所有设备查询必须同时遵守租户边界。设备绑定接口从 JWT 获取 `tenantId` 和 `userId`，不得接受客户端指定其他用户。

## 7. API 设计

### 7.1 绑定或刷新设备

```http
POST /api/tenant/push-devices
Authorization: Bearer <tenant_token>
Content-Type: application/json

{
  "clientId": "个推 ClientId",
  "platform": "android",
  "appVersion": "1.0.0"
}
```

响应：

```json
{
  "message": "推送设备绑定成功"
}
```

行为：

- 校验 ClientId 格式和长度。
- 按 ClientId 执行 upsert。
- 身份字段只从 JWT 获取。
- 更新 `enabled=true` 和 `lastSeenAt`。

### 7.2 解除当前设备

```http
DELETE /api/tenant/push-devices/current
Authorization: Bearer <tenant_token>
Content-Type: application/json

{
  "clientId": "个推 ClientId"
}
```

只允许解除当前登录用户拥有的设备。

### 7.3 刷新在线状态

APP 每次回到前台或重新登录时重复调用绑定接口即可，不额外设计心跳接口。

## 8. 新消息推送流程

客户发送消息后的顺序：

1. 服务端验证客户、渠道和会话。
2. 消息写入 MongoDB。
3. 更新会话摘要和未读数。
4. 向 `tenant-{tenantId}` 与 `channel-staff-{channelId}` 广播 `message.new`。
5. 根据渠道授权客服与当前接待客服确定通知接收人。
6. 查询接收人的有效 Android ClientId。
7. 调用个推发送通知。
8. 个推失败时记录非敏感错误，不回滚已经保存的聊天消息。

接收人规则：

- `waiting` 会话：通知该渠道有权限接待的在线/有效客服，可根据现有分配规则进一步收窄。
- `active` 会话：优先只通知当前接待客服。
- 客服自己发送的消息、机器人消息、系统消息不触发客服 APP 推送。
- 黑名单、无效设备和已停用设备不推送。

为避免多实例重复推送，推送应只在成功创建消息的请求实例执行，并依赖现有 `clientMessageId` 幂等机制；需要时以 Redis 短期键防止同一消息 ID 重复推送。

## 9. 通知内容和载荷

通知标题示例：

```text
忆梦云客服 · {渠道品牌名}
```

通知正文：

- 文字：显示经过长度限制的文本摘要。
- 图片：`[图片]`
- 视频：`[视频]`
- 文件：`[文件] 文件名`
- 敏感环境可配置为固定文案“您有一条新的客户消息”。

透传数据只放导航所需字段：

```json
{
  "type": "message",
  "messageId": "...",
  "conversationId": "...",
  "channelId": "..."
}
```

不得放入 JWT、客户手机号、完整文件地址或其他隐私数据。

## 10. APP 原生桥接

建议自定义 `YmkfNative` Capacitor Plugin，提供：

```ts
interface YmkfNativePlugin {
  getPushClientId(): Promise<{ clientId: string }>
  getLaunchNotification(): Promise<PushPayload | null>
  setCurrentUser(options: { loggedIn: boolean }): Promise<void>
  getAppState(): Promise<{ state: 'active' | 'background' }>
}
```

原生层向网页发送事件：

```text
pushClientIdChanged
notificationOpened
appStateChanged
```

网页端增加统一适配器：

- 普通浏览器环境无插件时直接跳过，不影响现有网站。
- Capacitor 环境登录成功后绑定 ClientId。
- 收到 `notificationOpened` 后验证字段并通过 Vue Router 跳转。
- 退出登录前调用解绑接口。

## 11. WebView 配置

`capacitor.config.ts` 目标配置：

```ts
server: {
  url: 'https://user.ymfk.top',
  cleartext: false,
  allowNavigation: ['user.ymfk.top'],
}
```

安全要求：

- 只允许业务域名导航。
- 外部链接交给系统浏览器。
- 禁止忽略 TLS 证书错误。
- 禁止启用任意文件 URL 访问。
- Android 截图和最近任务缩略图是否屏蔽，需要根据客服隐私要求决定。
- WebView User-Agent 增加 APP 标识，例如 `YMKF-Android/1.0.0`。

## 12. Android 系统行为

### 通知权限

Android 13 及以上启动后在合适时机请求 `POST_NOTIFICATIONS`。用户拒绝后提供设置入口，但不得循环弹窗。

### 通知渠道

至少创建：

```text
ymkf_messages    客户新消息，高重要性，声音和振动
ymkf_system      系统通知，默认重要性
```

通知渠道创建后声音策略由系统管理；修改声音通常需要新渠道 ID 或引导用户进入系统设置。

### 返回键

优先级：

1. 关闭网页弹窗。
2. 会话详情返回 `/m/messages`。
3. WebView 有历史时后退。
4. 首页再次返回时退出或进入后台。

### 文件与媒体

需要验证：

- 相机和相册上传。
- Android 文件选择器。
- 图片、视频和文件预览。
- 下载权限及 DownloadManager。
- 麦克风权限仅在以后增加语音消息时申请。

## 13. 前后台去重

推荐策略：

- APP 前台且目标会话正在显示：只更新页面，可不展示系统通知。
- APP 前台但不在目标会话：允许显示应用内提示，可选择保留系统通知。
- APP 后台或被杀死：显示个推系统通知。
- 使用 `messageId` 作为去重键，防止 Socket.IO 与推送点击后的补拉产生重复消息。

服务端无法可靠知道 WebView 当前正在查看哪个会话，因此页面可在前后台切换或会话切换时上报短期状态到 Redis；第一版也可只依据 APP 前后台状态处理，避免过度设计。

## 14. 开发阶段

### 阶段一：APP 壳

- 初始化 Capacitor 和 Android 工程。
- 固定加载 HTTPS 用户后台。
- 完成启动页、图标、返回键、文件上传和外链处理。
- 验证登录状态持久化。

### 阶段二：设备绑定

- 接入个推 SDK并获取 ClientId。
- 实现原生桥接。
- 新增 `PushDevice` 模型与绑定/解绑 API。
- 登录、退出和 ClientId 更新时同步绑定状态。

### 阶段三：消息推送

- 封装服务端个推客户端。
- 在客户消息成功持久化后触发推送。
- 实现通知点击跳转和登录后延迟跳转。
- 处理多设备、失效 ClientId 和重复消息。

### 阶段四：发布

- 配置正式签名和版本号。
- 开启 R8/ProGuard，并添加个推要求的保留规则。
- 生成签名 APK/AAB。
- 在 Android 8、10、12、13、14、15 的代表设备上验证。

## 15. 验收清单

### 基础功能

- APP 只能加载 `https://user.ymfk.top`。
- 登录、退出、自动登录正常。
- 手机端消息、渠道、员工、公告和资料页面正常。
- 图片、视频和文件上传与查看正常。
- Android 返回键行为正确。

### 实时与通知

- APP 前台能够通过 Socket.IO 即时收到消息。
- APP 后台能够收到通知栏消息。
- 从最近任务划掉 APP 后仍能收到个推通知。
- 点击通知打开正确会话。
- 未登录时先登录，随后打开目标会话。
- 同一条消息不会重复展示。
- 多账号切换后通知不会发送给旧账号。
- 当前接待客服和渠道授权边界正确。

### 安全

- APK 中不包含 `MasterSecret`。
- 服务端日志不打印 JWT、ClientId 全值或客户隐私。
- API 无法绑定到其他租户或其他客服。
- TLS 证书异常时 APP 拒绝连接。
- 推送载荷不包含完整消息附件和敏感资料。

## 16. 发布配置建议

初始版本：

```text
versionName: 1.0.0
versionCode: 1
minSdkVersion: 24
targetSdkVersion: 使用当前稳定 Android SDK
```

版本升级规则：

- 每次发布递增 `versionCode`。
- 用户可见版本使用语义化版本号。
- 签名文件及密码不提交 Git，应由安全环境或 CI 密钥保存。
- 测试和正式个推应用应分开，避免测试通知发送到生产设备。

## 17. 开发前待提供信息

开始实际工程开发前需要：

1. 个推 `AppId`、`AppKey`、`AppSecret`、`MasterSecret`。
2. 最终 Android 包名。
3. APP 显示名称。
4. APP 图标和启动页素材。
5. 是否需要隐藏通知正文。
6. 正式 Android 签名方案。
7. 确认 `https://user.ymfk.top` 的证书链在 Android 设备上可信。
